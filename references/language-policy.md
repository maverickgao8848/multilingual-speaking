# Language policy

## Defaults

| Code | Default variety | Core relationship choice |
|---|---|---|
| `es` | neutral Latin American Spanish | teach both `tú` and `usted`; default to `usted` with unfamiliar service staff when the pack calls for formality |
| `fr` | standard French from France | distinguish `tu` and `vous`; default to `vous` with unfamiliar adults and service staff |
| `de` | standard German from Germany | distinguish `du` and `Sie`; default to `Sie` in unfamiliar or formal service encounters |
| `ja` | standard Japanese | use です／ます style; model natural subject omission and role-appropriate service language |
| `ko` | Seoul standard Korean | use 해요体 by default; introduce 하십시오体 only when the role and setting require it |

Preserve a learner's valid regional choice. Label Spain-specific Spanish when it differs materially from the Latin American default.

## Script display

- Spanish, French, and German: show the target expression and concise Chinese meaning.
- Japanese: show `surface`, then `reading` when kanji occurs. Show `romanization` only when requested or when a true beginner cannot yet read kana.
- Korean: show `surface`; use `reading` only to teach an actual sound change. Show `romanization` only when requested or when the learner cannot yet read Hangul.
- Never make romanization the main answer channel. Fade it as soon as the learner can use the native script.

## Pronunciation boundaries

Only assess pronunciation from audio that was actually heard. Text can support prospective tips—such as French liaison, German final devoicing, Japanese mora timing, or Korean batchim changes—but not a claim about what the learner pronounced.

## Register handling

Choose one relationship before role-play and keep it stable. If the situation changes—for example, the learner starts speaking to a friend after addressing a clerk—announce the relationship change briefly. When two forms are pedagogically useful, show them as a pair in preview but rehearse the one appropriate to the chosen role.
